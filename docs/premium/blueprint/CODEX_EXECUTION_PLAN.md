## سجل البوابات

على فرع التطوير أنشئ سجلًا يذكر SHA دخول وخروج المرحلة، حالة كل اختبار، نوع الدليل، الجهاز/النظام، fixture وإعداداته، أثر قابل للفتح، الانحراف، المخاطر وخطة العودة. أنشئ checkpoint قابلًا للرجوع محليًا بعد بوابة ناجحة؛ لا نشر أو دمج. تراجع عن تغييرات الكود على فرع التطوير مع الاحتفاظ ببيانات الاختبار، وتعامل مع أي ترقية بيانات منفذة وفق خطة الإصدار.

قبل P01، حدّث سجل المواقع الحالية من الكود بدل نسخ `implemented`. بعد كل مرحلة، تحقق من كل صف يخصها في Protected Requirements وQA؛ لا تغيّر معنى معرّف اعتماد. أضف صفوفًا لأي عيوب جديدة. استثناءات أو اشتراطات وثائق المشروع الأقدم تُقرأ كأدلة نطاق؛ حدود المهمة الحالية وقيود حماية الفروع مقدمة عليها.

حالات القبول: PASS عند تحقق القياس المطلوب بالبيئة المحددة، FAIL عند إخفاق شرط واحد، BLOCKED عند عدم توفر الجهاز/الموقّع/المادة، NOT RUN عند عدم التنفيذ. الدليل الجزئي يكتب بجوار الحالة. العيوب P0، فقد البيانات، عدم تطابق التوقيع، تجاوز الخصوصية، أو غياب متطلب محمي تمنع التقدم في المسار المتأثر. لا يُرقّى أي اختبار محاكاة إلى دليل جهاز.
